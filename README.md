For my final project, I chose to use a directed graph to represent some of the connections between a mathematical structure called "Covering Systems." I wrote two functions to analyze these directed graphs. One of my functions, "loop" finds all paths that return to the original value quickly. The other function, "push" finds all paths that visits all values quickly.

Coverings are an interesting object to some mathematicians. They represent a way of looking at the whole numbers, and they reveal lots of properties of prime numbers and divisibility. For the purpose of a reader and grader of this final project, it suffices to understand that a covering system can be represented as a graph node, and that the operation of multiplication on a given covering system is interesting enough to consider it as a directed edge that can be formed. This structure has the start of the edge as some initial covering, and the end of the edge as the covering created by multiplying the starting covering by some prime number. I will include a more in-depth explanation of covering systems at the end of this README, if whoever reads this is interested. However, I attest that it suffices to know that covering systems and the multiplicative interactions between them can be represented as a directed graph.

I created a class to represent coverings, and I used structs to represent connections (edges) and my graphs as a whole.

One important choice I made in defining the structure of my graph was to use integer indexes instead of memory addresses to point to specific coverings in a graph. These indexes would reference a spot in the covering object vector stored in the graph, allowing O(1) access, like a pointer itself. I made this choice because "equal" coverings can and could be made in many different ways. Testing if two objects were mathematically equal, and then pointing any references to either one by an index in a vector, using an integer, was the smoothest way to allow "equal" covering objects, those with the same moduli and residue attributes, to be treated as the original object and allowing the latter object to be erased. This method was most efficient, so once the seed_code and lcm were calculated for a covering (in the moduli-residue sense), they need not be calculated again.

My code allowed for two different graph "structures", of the same definition in the "generate.h" file, to be generated. The first graph creation focused on counting "seeds" (a way of grouping covering systems), and the prime numbers that generated them. This graph was a spider graph, one with all covering nodes connected to the input covering and only the input covering. The connections between coverings of the same seed would be indicated implicitly by their seed_codes, but need not be explicitly expressed in the code. The user would then primarily use this first graph to understand the primes necessary for creating a graph of the second structure, although there exist many uses of accessing the data stored in this first graph as well.

The second graph structure has all coverings that can be generated from a single input covering. The connections between each covering indicate their direction and the prime that, times the first node, equals the second node. With this second graph I coded two separate depth-first traversals. I used a third struct, the "path", to keep track of an instance of a possible traversal, in terms of both coverings visited, and primes used. The first traversal would append to a vector of these paths all paths that resulted in a "loop", returning back to the same seed as began with. This information is very useful in understanding the ways these prime connections, thought of as directed edges, turn around and cycle. The second traversal investigated the opposite notion, the way the directed edges might keep going forward, and finding new seeds. This method created a vector storing all paths such that the path reached every possible seed. 

One consideration with these functions was how to traverse. I choose depth-first traversal for the "cycle" information gathering because I would be returning to certain seeds multiple times in my loops. A breadth-first traversal would have been cumbersome because of this returning: a node being marked as "visited" would do little good with these directed edges returning to it in a different direction. A depth-first traversal was also ideal for finding the paths that visited all seeds, as once a path cycled, it could be disregarded. This method kept only the paths with high potential in consideration.

Covering Systems Postscript!: 

A congruence takes the form (a mod b), which "covers" all integers that give remainder (residue) "a" when divided modulo "b". A set of congruences form a covering system if every integer falls into one or more of the congruences. A basic example of a covering system is the two congruences (0 mod 2) and (1 mod 2). (0 mod 2) covers all even numbers, as even numbers give remainder zero when divided by 2. (1 mod 2) covers all odd numbers, as odd numbers give remainder one when divided by two. Together, these two congruences cover all even numbers and all odd numbers, thus the cover all integers. We conclude that (0 mod 2) and (1 mod 2) form a covering.

I am interested in more complicated covering systems, some examples of which will be in my video. One important operation you can do to a covering is add an integer to all residues. For example, adding 1 to our example covering, (0 mod 2) becomes (0+1 mod 2) = (1 mod 2), and (1 mod 2) becomes (1+1 mod 2) = (2 mod 2) = (0 mod 2). These two congruences, taken together, still cover all integers (in this case they form the exact same covering!). 

The most important operation you can do to a covering system (at least for me!) is multiply a prime number to all residues. For example, multiplying 3 to our example covering: (0 mod 2) becomes (0\*3 mod 2) = (0 mod 2), and (1 mod 2) becomes (1\*3 mod 2) = (3 mod 2) = (1 mod 2). We still have a covering! This operation is way more fun on more complicated covering systems!

We call the set of all covering systems attainable by adding integers to an original covering a "seed". We are most interested in the primes, that times an original covering, produce a new covering in a seed that has not been generated yet. We call these prime numbers "seed primes".

My project attempts to investigate what happens in the structure of all possible coverings generated from an input covering when we continue multiplying by different seed primes. The work in this project has pointed to the possibility that this multiplication is commutative (independent of order) and exact (offsetting within a seed and multiplying by a prime is equivalent to multiplying by a prime and then offsetting the same amount in the new seed!). Next steps are to try to investigate these possibilities with even more coverings, and if they continue to hold, try to prove the generalized case! Thanks code!
