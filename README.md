For my final project, I chose to use a directed graph to represent some of the connections between a mathematical structure called "Covering Systems."

Coverings are an interesting object to some mathematicians. They represent a way of looking at the whole numbers, and they reveal lots of properties of prime numbers and divisibility. For the purpose of a reader and grader of this final project, it suffices to understand that a covering system can be represented as a graph node, and that the operation of multiplication on a given covering system is interesting enough to consider it as a directed edge that can be formed. This structure has the start of the edge as some initial covering, and the end of the edge as the covering created by multiplying the starting covering by some prime number. I will include a more in-depth explanation of covering systems at the end of this README, if whoever reads this is interested. However, I attest that it suffices to know that covering systems and the multiplicative interactions between them can be represented as a directed graph.

I created a class to represent coverings, and I used structs to represent connections (edges) and my graphs as a whole

One important choice I made in defining the structure of my graph was to use integer indexes instead of memory addresses to point to specific coverings in a graph. These indexes would refrence a spot in the covering object vector stored in the graph, allowing O(1) access, like a pointer itself. I made this choice because "equal" coverings can and could be made in many different ways. Testing if two objects were mathematically equal, and then pointing any refrences to either one by an index in a vector, using an integer, was the smoothest way to allow "equal" covering objects, those with the same moduli and residue attributes, to be treated as the original object and allowing the latter object to be erased. This method was most efficient, so once the seed_code and lcm were calculated for a covering (in the moduli-residue sense), they need not be calculated again.

My code allowed for two different graph "structures", of the same definition in the "generate.h" file, to be generated. The first graph creation focused on counting "seeds" (a way of grouping covering systems), and the prime numbers that generated them. This graph was a spider graph, one with all covering nodes connected to the input covering and only the input covering. The connections between coverings of the same seed would be indicated by their seed_codes, but need not be explicitly expressed in the code. The user would then primaraly use this first graph to understand the primes necessary for creating a graph of the second structure, although there exist many uses of accessing the data stored in this first graph as well.
